## Findings

1. Pre-existing, not introduced by CIFIX (blocking for the "save works without JS" claim): a real browser form POST with JavaScript disabled is rejected, 403 {"detail":"invalid_csrf"} (screenshot nojs_422.png). The override dialog form has no hidden _csrf_token input; the token is added only by csrf.js / htmx-csrf.js. So the no-JS save and the no-JS 422 are not reachable from a browser; the server-side re-render path itself is fine (verified with a token on a raw request). Fix belongs in the dialog form (hidden _csrf_token) or an ADR decision that no-JS saves are unsupported. The CIFIX diff does not touch the form.
2. Cosmetic, unchanged by CIFIX (same CSS rule as before): in the no-JS card at 375 (card width 343) the third scope option "every month (default)" wraps to three lines and its label is clipped inside the segmented control (nojs_light_375.png). Not a diagnostic signal; triage.
