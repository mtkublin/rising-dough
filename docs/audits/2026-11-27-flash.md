# T-UR96 planned save flash (2026-11-27)

Diagnosis of POST /planned from the new-entry dialog. No template, CSS or response code changed.

## Matrix

| Opened on | HX-Refresh in response | Flash "Planned entry saved" in `#flash-region` | Source |
|---|---|---|---|
| /today | no | yes | integration + e2e |
| /ledger | no (HX-Reswap none) | yes | integration + e2e |
| /ledger?tab=planned | no (HX-Reswap none) | yes | integration + e2e |
| /plan | no | yes | integration + e2e |
| /accounts | no | yes | integration + e2e |

Cause of the older observation (d5 audit line 25): the pre-ADR-0143 `HX-Refresh` path, replaced by
`refresh_unless_on` (stale events, no reload; T-UR48a, BUGA2). The success flash is an out-of-band
swap into `#flash-region` from `saved_response`, which survives because no page reload happens.
Result: no page loses the flash today; the fix is the regression tests only
(`tests/integration/web/test_planned_save_flash.py`, `tests/e2e/test_save_flash.py`).

## Audit scope

The browser sweep at 1440/1024/375 was not run separately: nothing visual changed, and the e2e
journey (Playwright, GitHub e2e.yml) opens the dialog on each page, saves, and asserts the flash
text and the stored amount (1234). The failing-save path (Step 3b) is covered by
`tests/e2e/test_planned_validation.py` (visible field error, dialog stays open, nothing stored).
