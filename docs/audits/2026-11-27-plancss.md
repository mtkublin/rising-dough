## T-UR85: unbudgeted list columns vs the main table

Test `test_every_column_starts_where_the_main_table_column_does` (1440 and 1024), first unbudgeted row against the first main row: category and bar cells start at the same left x (+-1 px); spent, status and actions cells end at the same right x (+-1 px). Both pass on the unchanged CSS.

Finding: the grid tracks (`--ledger-cols`: fixed category, `minmax(0, 1fr)` bar, fixed spent, status, actions) are identical in both tables and both tables get the same width, so the column edges already agree. The 965 vs 995 and 1170 vs 1085 offsets of the 2026-11-27 PLANCAT measurement are the left x of right-aligned cells whose text differs ("spent / budget" figures, a "set budget" button vs a status text): the cell box shrinks to its content, the column edge does not move. The test therefore compares the column edge each cell is aligned to. No CSS change.

## T-UR71: Plan/year at 1024 and 375

Test `test_year_grid_scrolls_in_its_region_not_the_page` (1024 and 375): `document.scrollingElement.scrollWidth <= innerWidth` (no page-level horizontalScroll); the year region has `scrollWidth > clientWidth` (the grid scrolls inside it, intended until T-UR64) and its right edge is inside the viewport; no element outside a `.rd-table-scroll` region reaches past the viewport. Passes on the unchanged CSS (the region is already constrained).

Triage: the skill's `overflowingElements` diagnostic counts every element whose right edge is past the viewport, including the cells of the grid that sit inside the scroll region (20 entries at 1024 and 375 in the CHIPMOB audit, `horizontalScroll: false`). That is the intended in-region scroll, not an overflowing ancestor; the count only drops to 0 when the grid is rebuilt mobile-first (T-UR64, deferred).
