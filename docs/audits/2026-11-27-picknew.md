## Findings

1. BLOCKING (Behavior, `src/budget_planner/web/static/rd/js/combobox.js:109-112`): creating a category does not pick it.
   htmx 2.0.11 fires `htmx:beforeSwap` on the swap TARGET, so `detail.elt` is the slot `div[data-js=combobox-create-slot]`
   (observed in the browser: `elt=DIV.combobox-create-slot src=combobox-create`), and
   `detail.elt.matches('[data-js="combobox-create"]')` is false. The handler returns, htmx swaps the option markup into the
   slot, the panel stays open with the stale no-match block and a chip `PROBE8432 / expense` inside it, no `category` field
   is set, and saving posts `amount, account_id, operation_date, description` without a category: `POST /transactions` -> 422
   dialog, nothing saved (reproduced; picking an existing category in the same dialog saves 200 and the entry shows in
   `/ledger`). Fix: use `detail.requestConfig.elt` (the button) in `beforeSwap` (and `configRequest`'s `detail.elt` is
   fine). The journey `tests/e2e/journeys/test_picker_create_category.py` should then fail on current code; it was not run here.
2. Minor (Layout): at 1440x900 the dialog height changes by 16 px between the picker closed/open and the error/chip states
   (centred, so the top edge moves 8 px). Not seen at 1024/375.

Result: FINDINGS (1 blocking). Save-after-create, selected-state layout and the "ledger shows the entry with the new
category" check could not be completed until finding 1 is fixed; re-audit then.
