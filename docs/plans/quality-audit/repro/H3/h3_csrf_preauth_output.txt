== C1 login CSRF
no cookie, no token -> 403 {"detail":"missing_cookie"}
cookie, no token -> 403 {"detail":"invalid_csrf"}
cookie, wrong token -> 403 {"detail":"invalid_csrf"}
attacker-chosen 1-char cookie 'a' + same form token -> 303 (303 = accepted: no format/signature check on the token)

== C2 CSRF token lifecycle across login / logout
token before login == after login == after logout: True

== C3 header vs form precedence
empty header + valid form token -> 303
wrong header + valid form token -> 403
text/plain + header -> 303 (header alone suffices; cross-site fetch cannot set it without CORS preflight)
text/plain, no token (classic cross-site form) -> 403
PUT without token -> 403
PATCH without token -> 403
DELETE without token -> 403
