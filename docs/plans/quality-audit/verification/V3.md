## Method

- Independence rule followed: only id, title, severity and Location(s) were read from `tracks/F-tests.md` and `tracks/H2-isolation.md` before forming verdicts. Description/Evidence were not read. Raw data used as data only: `baseline/mutmut-real-gaps.md` header, `repro/F/functions_without_unit_tests.out`, `repro/F/coverage_without_ellipsis_exclusion.txt`, `repro/H2/h2_01_anchor_oracle_output.txt`, `repro/verify/V2/g01_fx_relative_url.out`.
- Scope: every High in F (F-01..F-10, F-12, F-13, F-14); H2-01; random sample of Mediums.
- Mutant re-creation (F-01..F-10): hand-written single-site mutants in `repro/verify/V3/mutate.py`. The script writes one mutation into the real module, runs ONLY the targeted unit test file(s) with `uv run pytest --no-cov -p no:cacheprovider -n 0 -q -x -o addopts=`, then always reverts with `git checkout -- <file>` (try/finally). Output: `repro/verify/V3/mutants.out`. 26 mutants run (more than the required 2 per finding).
  - Limitation: only the unit test file(s) for the module were run, not integration tests. A survivor here means "unit tests do not kill it"; an integration test could still kill it. For F-01 I grepped: `format_money` is referenced by tests only in `tests/unit/domain/test_money.py` (plus the `templating.py` wrapper), so integration cannot kill F-01a.
  - F-03a/F-03b/F-09a patterns occur twice in the file, so those mutants changed both sites at once (all KILLED); I then added single-site forecast mutants F-03c/d/e.
- Sample of Mediums: population (12) = F-11, F-15, F-16, F-17, F-18, F-19, F-20, F-21, F-22, F-27 (F) + H2-02, H2-03 (H2). `random.seed(33); sorted(random.sample(mediums, 4))` -> **F-16, F-17, F-18, F-27** (33%, above the 20% floor). I also read H2-02 and H2-03 against the code as a bonus.
- Operator facts applied: prod PLN-only, one active user, more users soon.
