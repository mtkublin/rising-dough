## Method

- Independence (plan section 6): from the track files I read only each finding's id, title, severity and Location(s) (a grep of those lines; a few Location lines carry short inline notes, e.g. A-01 names the `/ 100.0` site, B-01 carries a calibration remark). Description / Evidence / Impact sections and `repro/` scripts of the tracks were NOT opened. Verdicts come from the cited code plus my own scripts.
- Repros: `repro/verify/V1/*.py` against `/tmp/verify-V1.sqlite`, a copy of `data/demo.sqlite` migrated in place (the copy only; `data/budget.sqlite` never opened). The DB URL is set explicitly in `_common.py` / `_web.py`. Web repros use the FastAPI TestClient with a seeded session on the scratch copy. Outputs are in `out_*.txt` beside the scripts. No test suite was run.
- Scope: all 18 Critical/High findings (A-01..A-08, B-01..B-03, C-01..C-07) plus a seeded sample of Mediums. Medium population = A-09..A-17 (9), B-04..B-10 (7), C-08..C-17 (10) = 26; 20% = 6, I took 7. `random.seed(11); random.sample(mediums, 7)` -> **A-15, B-09, C-08, C-09, C-10, C-15, C-17**. I additionally checked C-13 (cheap, shares the recurring repro).
- Operator facts used for severity (section 5.1): prod is PLN-only (no FX / 0- or 3-decimal currencies), one active user (more soon), no reconciliation ever used an income/expense category, probably no blank-day-of-month rule starting after the 28th. "Wrong money today" = Critical only if it bites on that data; otherwise High (latent).

## Per-finding notes

- **A-01 / C-03**: line 100 and the net-card header use `/ 100.0` on native `balance_minor`. For a JPY account (0 decimals) the stored value is whole yen. /accounts renders it correctly (`500,000 JPY`, see `out_a01.txt`), so the two screens would disagree. I could not see the Today row itself because the demo list is capped at 7 rows; verdict rests on the template line. Not Critical: prod has no such account.
- **A-02**: `_spend_by_category`, `_income_vs_expense_monthly`, `_largest_items` and averages add `t.amount` without account currency lookups. Only wrong with a second currency.
- **A-03**: the budget/committed side is converted to base through `base_amount_converter`; spent is not. The `min(id)` placement of the overlay was not exercised.
- **A-04**: see `out_a04.txt`. The planned side and the recurring side both count the same occurrence in the forecast helper, which makes the overlay under-forecast the unaccounted budget (conservative direction, still wrong).
- **A-05**: pure code proof. In the fallback, `next_income_date` = last day of month, `_committed_by_category` end is exclusive, so committed items on the last day are excluded and the divisor is one short on every day of the month.
- **A-06 / C-02**: all five policies located in code. Real prod only hits them when a non-base account exists.
- **A-07**: different totals for the same label depending on which page; today identical because every account is PLN.
- **A-08 / C-10**: `out_c10.txt`, `out_money.txt`. Canonical `parse_amount_str` also accepts `1e3`, `1e400` (Decimal exponent), `1_000` and non-ASCII digits; callers that bypass it crash on NaN/Infinity.
- **B-02**: `out_b02.txt`. The comment in `services/balance.py` ("schema CHECK blocks it") is false; only `account_id <> dest_account_id` is checked. Recoverable only by deleting the row.
- **B-03 / C-16**: undo replays the newest `audit_log` row for the entity (no operation filter in the recurring variant, no `user_id` filter on the read) and writes the planned-row restore with raw SQL, so no audit row is produced for the restore. The normal immediate-undo case does work.
- **C-01**: `out_c01.txt`. `stored_amount = abs(delta)` for non-adjustment categories; the sign then comes from category direction, so the docstring claim ("sign coerced to match") is not implemented. The modal lists all non-system categories, so it is UI-reachable.
- **C-05**: `out_c05.txt`; /today, /forecast, /ledger still 200 (no crash), but a live rule on a deleted account keeps feeding forecasts and can be promoted.
- **C-06**: `out_c06_c13.txt`. Promote path calls `advance_next_due(..., rule.day_of_month, ...)` with None for blank, the stub's anchor is `from_date.day`, so one clamp permanently shifts the schedule.
- **C-07**: `out_c07.txt`.
- **C-09**: not reproduced under real concurrency; verdict from the missing guard, deferred BEGIN, and no unique index.
