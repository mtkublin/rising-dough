### E-01 — HTMX error responses never reach the user
- **Severity / confidence:** Medium / Confirmed. **Track / root cause:** E / htmx-contract.
- **Location(s):** `errors.py:55-77` (`_flash_fragment`), `errors.py:73-77,91,107,129` (404/409/422/500 → OOB flash for HTMX), `static/js/app-init.js:4-10` (only 422/429 forced to swap), `static/js/users-admin.js:73-82` (409 only inside `[data-users-admin]`), `templates/base.html:6-7` (htmx-config sets no `responseHandling`), `static/htmx-csrf.js:36-41`.
- **Description:** htmx 2 does not swap 4xx/5xx by default. The server builds an `hx-swap-oob` flash for 404, 409 and 500 (`partials/_flash.html:12`) but the client whitelists only 422, 429 and (users page) 409. The flash and its "reference id" never render. A CSRF 403 (JSON, not even HTML) and a missing-token no-op in `htmx-csrf.js:38-41` are equally invisible. There is no `htmx:responseError` handler.
- **Evidence:** `runtime_audit.py` probe P3: from `/ledger` run `htmx.ajax('GET','/transactions/999999/edit', …)`. Output (`runtime_audit.out.json`): `"error_flash": {"respErrors": 1, "flash": "", "flashAssertive": ""}`. The server answered 404 with the flash fragment, `htmx:responseError` fired once, both live regions stayed empty.
- **Impact:** A failed save (500), a stale-row conflict (409) or an expired CSRF token looks like "nothing happened". The user re-clicks or assumes success.
- **Mitigation:** One global `htmx:beforeSwap` handler in `app-init.js` (replacing the 422/429 block): for any 4xx/5xx whose response contains `hx-swap-oob`, set `shouldSwap = true; isError = false`; and add a `htmx:responseError`/`sendError` fallback that writes a generic message to `#flash-region-assertive`. Keep it in the behaviour layer so it survives the redesign. Add one e2e test (error → flash visible).
- **Effort:** S. **Related:** ADR-0107, `tests/e2e`.

### E-02 — Half the `*-stale` contract has no listener

### E-03 — Inline 2-decimal money formatting bypasses the filters
- **Severity / confidence:** High / Confirmed (formatting); reach into real data depends on JPY/KRW accounts. **Root cause:** money-arith (template-logic).
- **Location(s):** 35 occurrences of `"{:,.Nf}".format(x / 100.0)`: `today/index.html:42,52-55,89,92-93,100`, `today/_upcoming.html:43`, `today/_afford_preview.html:3,5`, `ledger/_table.html:69`, `ledger/index.html:98,105,114`, `plan/_forecast_tab.html:85-88`, `plan/_analytics_bundle.html:17,43,46,110`, `plan/_year_tab.html:47,61,63,75`, `plan/_budget_tab.html:6-9,36,56-57`, `accounts/index.html:23,31,35,39`, `partials/budget/_override_form.html:56`, `partials/recurring/_formula_preview.html:4`. And one that feeds a form value: `partials/recurring/_promote_inline_row.html:38` (`(prefill_amount_minor / 100)|round(2)`).
- **Description:** `templating.py:23-47` provides `money`, `money_num`, `money_major` that use `currency_decimals()` (JPY/KRW = 0). These sites hard-code 100 and 2 decimals and use float division. `today/index.html:100` and `accounts` rows apply it to per-account balances, so a JPY account displays 100x too small. `_promote_inline_row.html:38` prefills an editable amount, so a JPY promote would prefill 1/100th and persist it if submitted. The same macros elsewhere (`_amount.html:14`) use the filter correctly.
- **Evidence:** `docs/plans/quality-audit/repro/E/money_format_repro.py` output: `PLN: inline 1,234.56 / money_num 1,234.56`, `JPY: inline 1,234.56 / money_num 123,456`.
- **Impact:** Wrong money shown for any 0-decimal-currency account or base currency (T-JPY lets users create them).
- **Mitigation:** Compute display strings in the view model (`money_num(x, ccy)` with the right currency per row); ban `/ 100` in templates with a one-line lint test (grep for `/ 100` in `templates/`). Pass the currency into every call site (the `today` rows already carry `row.currency`).
- **Effort:** M. **Related:** ADR-0008, E-04, Track A (money formatting).

### E-04 — Mixed-currency sums labelled "PLN"
- **Severity / confidence:** High / Confirmed. **Root cause:** money-arith + layer-leak (router logic shown by a template).
- **Location(s):** `routers/ledger.py:344-374` (`_recurring_summary`), `routers/ledger.py:409-413` (`planned_total_minor`), rendered at `templates/ledger/index.html:98-106,114` with a literal `PLN`.
- **Description:** Rows carry per-account `currency` (`ledger.py:102,134,216`) but both aggregates add raw minor units across accounts without FX conversion, and the template prints "PLN" regardless of `settings.base_currency`. The actual-view `day_net` does convert (`ledger.py:255-281`), so the three views disagree on semantics.
- **Evidence:** `runtime_audit.py fx` on the scratch DB (`fx_probe.out.json`): recurring "Monthly out/in" strip is `13,755 / 23,253 PLN` both before and after flipping the account that owns the most rules from PLN to EUR. A converting aggregate would change. Demo data is all PLN, so the bug is latent today.
- **Impact:** As soon as a EUR/USD account has a recurring rule or pending planned row, the strip is wrong by the FX factor and mislabelled.
- **Mitigation:** Convert per row with `fx_service.convert_cached` to base (as `_actual_day_nets`), return `base_ccy` in the context, render with `money`. Move to a service function with a mixed-currency test (property: sum equals sum of converted parts).
- **Effort:** S–M. **Related:** E-03, ADR-0006, Track A.

### E-05 — Left-per-day / %-used derived again in templates
- **Severity / confidence:** High / Probable. **Root cause:** template-logic (duplicate derivation).
- **Location(s):** `today/index.html:28-36`, `plan/_budget_tab.html:2-12,56-59`, `_partials/components/_period_header.html:4-8`, `budget/index.html:102-108`, `plan/_analytics_bundle.html:24-35`, `_partials/components/_heatmap_cell.html:4-6` (sqrt scale tuned to "1600 PLN"). Authoritative values: `services/budget.py:583-587` (`left_daily_spend_minor`, Decimal, half-even) and `services/today.py:96-102`.
- **Description:** The service computes per-day with Decimal half-even; the hero (`today/index.html:32,42`) and Plan (`_budget_tab.html:12`) re-divide floats and let `format` round. The divisor differs by page (`days_left or 1` vs `summary.days_until_next_income or 1`). Zero-budget guards differ (`budget_minor > 0` vs `p > 0` vs `max_amount > 0`). Percent clamping is in templates (`[spent_pct,100]|min`).
- **Evidence:** Code citation only. Binary-float .5 cases and the unused `left_daily_spend_minor` field make a 1-minor-unit disagreement possible; not reproduced with real data.
- **Impact:** Today hero and Plan can differ by 0.01; thresholds ("over budget") evaluated on floats.
- **Mitigation:** Add `left_per_day_minor`, `spent_pct`, `committed_pct`, `remaining_after` to `MonthSummary` (or a `BudgetView` dataclass in `web/`), render only those; delete the `set` blocks. Survives the redesign as view-model work.
- **Effort:** M. **Related:** E-03, `services/budget.py:583`.

### E-08 — `bulk-select.js` is dead and unsafe if revived
- **Severity / confidence:** Low / Confirmed. **Root cause:** dead-code.
- **Location(s):** `static/js/bulk-select.js:62-70` loaded at `templates/base.html:74`.

- **Severity / confidence:** Low / Probable. **Root cause:** security-control / config-drift.

## 5. CSRF / CSP handling and kept behaviour JS

**Mechanism.** `CSRFMiddleware` double-submit (`middleware/csrf.py:155-183`): cookie vs `X-CSRF-Token` header or `_csrf_token` form field. HTML forms embed the field; htmx gets the header from `<meta name="csrf-token">` through `hx-ext="csrf"` on `<body>` (`base.html:31`, `htmx-csrf.js:36-47`); `passkeys.js` reads the same meta (`:21-24`, `:51`).

**`htmx-csrf.js` review.** Correct and small (49 lines). Defer ordering is right (htmx is sync in `<head>`, ext defer). Only unsafe verbs get the header. Issues: silently registers nothing if `window.htmx` is missing (`:29-32`); silently omits the header if the meta token is empty (`:41`), which then yields an invisible 403 (E-01). Token duplication with `passkeys.js` (E-10).

**CSP.** Prod policy (`Caddyfile.tpl:54`): `script-src 'self' 'nonce-…'`, `style-src 'self' 'unsafe-inline'` (ADR-0113 stopgap), `connect-src 'self'`, `form-action 'self'`, `object-src 'none'`. The frontend is compatible: zero inline scripts or handlers (grep), all behaviour is in `static/js`, delegated listeners. The nonce is never used (E-11). The app itself emits no CSP, so a request that bypasses Caddy has none (documented design, ADR-0036). The e2e harness injects the real policy and asserts no violations.

**Other kept JS.** `app-init.js` mixes four concerns (422/429 swap override, form reset, toast, view transitions); it contains the only view-layer undo flow, which reloads the page unconditionally after the undo request (`:59-61`, see Q3). `overlay-actions.js` and `budget-override.js` use window flags for idempotency (`__overlayActionsWired`, `__budgetOverrideWired`), `rd-wire.js` registers one `htmx:load` listener per `rdWire` call (7 callers, each scans every swapped subtree), `app-init.js` has two `htmx:beforeSwap` listeners. Low-value duplication (not a separate finding; fold into the redesign's JS cleanup). `bulk-select.js`: E-08.
