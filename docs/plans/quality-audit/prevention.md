## 0. Summary of the diagnosis

The 77 findings come from five systemic causes. Every control in §2 attacks at least one of them.

1. **No registry of "where does concept X live".** `CLAUDE.md` names principles (DRY, "one place for query helpers" in requirements §3.3) but not one concrete module. An agent given "show spent in base currency" has nothing to search for and writes the fifth FX converter. Evidence from git history: the diverging copies (`forecast._convert_native_to_base` in T-025 on 2026-10-24, `today_data._convert_minor` inside the bundled T-063/T-065/T-068 commit on 2026-10-26, `forecast._committed_future_for_category` in T-125 on 2026-10-27) were written in **different tasks days apart**, mostly sequentially. Parallel orchestrator items are therefore a *contributing* source (the bundled commit, and nothing in the brief stops two items from each adding a helper), **not the dominant one**; the dominant cause is that nothing makes a later task look for an earlier helper. The `pylint duplicate-code` run found 19 boilerplate blocks and none of the semantic duplicates (the FX converters differ in policy, not in text), so token-similarity detection is not a useful control here.
2. **Rules exist only as prose, and the prose is long and stale.** The layering, soft-delete, user-scoping and clock rules are in ADRs and `CLAUDE.md`. Enforcement exists for exactly one rule (user-id filter in SQL, `tests/architecture/test_user_id_filter.py`) and even that missed `web/routers/budget.py:387,394` because it checks SQL, not literal ids passed to services (Q-001). ADR-0022 literally says "Future enforcement option: a static-analysis rule" (never built).
3. **Gates are weaker than they look.** Coverage hides code (`...` exclusion, Q-014), the web test client supplies what production lacks (Q-058, the reason the FX bug Q-007 shipped), fixtures contain one user and no tombstones (Q-015), no test asserts agreement between implementations (Q-013), `just ci` omits four pre-commit checks (Q-044), and merge gating is self-attested (Q-041).
4. **Suppressions are free.** 121 `noqa` in `src` (37 `PLC0415`, 32 `PLR0917`, 18 `DTZ011`), with no reason requirement, hide the import cycle, the clock misuse and the wide signatures. Review sees a green CI.
5. **Review cannot see what no diff shows.** A reviewer (or review agent) reads the diff of one task. A duplicate is visible only against code the diff does not touch; a missing `user_id` is visible only against a rule the reviewer must remember. Controls must therefore fire in CI/pre-commit at the moment of writing, not rely on review.

### 1.3 Core question per class: why was it written, why did review not catch it

For each class: **Why written** (agent / human cause), **Why not caught** (review and gates), **Guidance gap** (artefact reference from 1.2).

#### duplicate-logic (Q-002, Q-003, Q-007, Q-008, Q-009, Q-010; also Q-023, Q-030, Q-032, Q-036, Q-071, Q-075)

- **Why written.** Each feature task (forecast T-025, overview T-063, forecast overlay T-125/T-127, Plan tab T-127) needed "convert to base", "month window", "expand recurring occurrences" and found no shared function that fit exactly, or did not look. Copies were written days apart by sequential tasks (see §0); the bundled multi-task commit and the absence of any shared-helper carve-out in the orchestrator brief (1.2 row 2b) make parallel items an additional, not the main, source. Each copy is locally reasonable (hence five missing-rate policies, seven amount parsers, six sign switches).
- **Why not caught.** Reviewers read one diff. The divergence is only visible against code outside the diff. No test asserts agreement (Q-013: none of 16 invariants exist). Coverage and mutation gates are blind to it by construction: each copy is individually tested (or not, Q-021). `pylint duplicate-code` finds boilerplate, not semantic copies (19 blocks, none of the FX copies).
- **Guidance gap.** No canonical-module table (CLAUDE.md), no search-before-write step in the brief (orchestrator), no reuse question in the handoff (CLAUDE.md, v2/v3 plans), "DRY" in requirements §3.3 is a slogan.

#### scoping-gap (Q-001; Q-026, Q-034, Q-060)

- **Why written.** The handler was written when only user 1 existed (v2 era); `user_id=1` is a natural constant for a single-user app, and the ADR-0061 multi-user rule arrived later.
- **Why not caught.** `test_user_id_filter` checks that SQL has a `user_id` predicate; a literal `1` *satisfies* it. Fixtures have one user (Q-015) so no test can fail. The repro for Q-001 needed a second user.
- **Guidance gap.** CLAUDE.md says "Single user, multi-account, multi-currency" in its first line; the ADR-0061 rule "every query scoped to the acting user" is not restated, and "never pass a literal user id" is nowhere.

#### layer-leak (Q-004; Q-033, Q-045, Q-074) and repo-bypass (Q-024, Q-049, same fix)

- **Why written.** Routers import repositories directly in 13 of 20 routers; there is no service layer for CRUD (Q-045), so the easiest correct-looking code path is router → repository. Validation lives only in `_promotion.validate_promotion` (Q-004): create/update routes never call it. Router SQL (Q-024) was added for undo endpoints because no service function existed.
- **Why not caught.** Layering is stated, not tested. The baseline's import-linter dry run shows 3 of 7 reasonable contracts kept and 4 broken today; nobody ran it. ADR-0022 names the enforcement option and defers it.
- **Guidance gap.** CLAUDE.md "Thin web, fat services" has no pointer to a check; the requirements §3.3 has no layering statement; ADR-0022's enforcement is a footnote.

#### money-arith (Q-005, Q-011; Q-029, Q-076) and date-boundary (Q-006)

- **Why written.** Minor-unit arithmetic and display were hand-rolled where needed (`/ 100.0` in 40+ templates, six sign copies, three rounding modes). The month/day arithmetic (Q-006) lacks a property test.
- **Why not caught.** All tests use PLN with two decimals and full months; the defects need JPY, a blank day-of-month, or a reconciliation with an income category. The reconciliation test is vacuous (Q-059). Mutation survivors (Q-016…Q-020) include exactly these boundaries.
- **Guidance gap.** CLAUDE.md states "amounts are positive integer minor units; direction from category.direction" but not "format via `money` / `domain.money`, never divide by 100", "one rounding mode", "one sign function".

#### weak-assertion (Q-016…Q-020, Q-055, Q-056, Q-058, Q-059; Q-022, Q-077) and missing-invariant-test (Q-013, Q-015; Q-021, Q-028)

- **Why written.** Tests were written to hit coverage lines and status codes (141 HTTP tests assert only the status, Q-059); fixtures grew without a second user or tombstones; the test client and the FX client factory are configured more generously than production (Q-058).
- **Why not caught.** The only test-quality gate is line/branch coverage at 90%, which Q-014 shows excludes 790 statements and 16 functions. There was no mutation score and no differential tests. The repo's own TDD rule ("tests first, 90%") is satisfied by weak tests.
- **Guidance gap.** No statement of what a test must assert (side effect, exact value, other user's rows absent). No mutation policy (the plan's earlier ADR number was withdrawn: 0095 is taken). Requirements §3 does not list mutation testing.

#### config-drift (Q-014; Q-044, Q-061, Q-066)

- **Why written.** The `...` regex was added to exclude `Protocol` stubs and matches every line containing `...`. Pre-commit and `just ci` evolved separately (ADR-0108, ADR-0120 moved the gate to pre-commit), and nobody owns "the two lists are equal".
- **Why not caught.** Nothing compares them. Coverage config is never read by a test.
- **Guidance gap.** ADR-0120 defines the pre-commit gate by cost, not by parity with CI.

#### ci-trust-boundary (Q-012; Q-040, Q-041, Q-042, Q-069)

- **Why written.** Environments were created for deploys ("prod-plan", drill environments) and given prod-grade secrets for convenience; the verified signing identity is "build.yml from any ref".
- **Why not caught.** Environment protection and branch policy are repository *settings*, not code: no diff shows them, no test reads them. ADR-0099/0100 state the intent ("keys live only in the `prod` environment") and the runbook claims a stricter setting than reality (Q-068).
- **Guidance gap.** CLAUDE.md "Releases & environments" states the rule well but cannot detect a violation. Findings in this class need a re-check after main's T-D158 changes (findings.md header note).

### 1.5 What review actually relies on (consolidated)

Today's review chain for an item is: agent self-check → pre-commit (ruff, mypy, affected tests) → orchestrator merge (reads the report, `diff --stat`) → PR CI (`just ci`) → drill gate. None of the five steps asks "does this duplicate something" or "does this satisfy a rule that is only prose". The strongest existing control, `tests/architecture/`, is under-used (two rule families). Controls in §2 therefore move rules from prose to the architecture directory and the pre-commit stack wherever feasible.

## 2. Prevention matrix (T-Q14)

### 2.1 Design principles (shared by all guards)

1. **Allowlist = ratchet, not escape hatch.** Each guard has one data file `tests/architecture/allowlists/<guard>.toml` (sorted, one entry per `path` with `count` and a `finding` field naming the Q-id). The test fails on **more** violations than allowed (new violation) **and on fewer** (the allowlist must shrink when a finding is fixed). Entries are therefore exactly the audit's findings, and remediation tasks (T-Q2xx) list the entries they delete. Counts per file rather than line numbers, so unrelated edits do not break them.
2. **Failure messages teach.** Every guard error names the rule, the canonical module and the Q-id/ADR, e.g. "FX conversion: use `services.fx.converter_for` (CLAUDE.md Canonical modules; Q-007)". This is how a rule becomes findable at the point of action, which prose in CLAUDE.md cannot achieve.
3. **Always run.** Guards live in `tests/architecture/` (or a lint hook) and must run on every commit, not only when testmon selects them (§1.2, pre-commit row). Control G0 below.
4. **One allowlist file per guard** (merge-conflict control: parallel items burn different allowlists; the files are added to the orchestrator hotspot list).
5. **New code starts at zero.** Allowlists are keyed to existing paths; a new file has no allowance. The Sourdough redesign (ADR-0107) templates therefore start strict.

### 2.2 Controls

Type: **G** automated guard (strongest), **S** structural, **R** written rule. "Verified by" is how T-Q15/T-Q16 prove the control works (a deliberately violating fixture or a dry run).

#### G0 — Make guards run on every commit (enabler)

- Parity note (T-Q15e): vendored `docs/application_redesign_handoff/` (ADR-0129) is excluded from the whitespace, eof, mixed-line-ending, djlint and detect-secrets hooks, like `docs/design/`, so `pre-commit run --all-files` in CI passes without editing vendored files.
- Add a pre-commit local hook `architecture-guards`: `uv run pytest tests/architecture -q --no-cov -p no:testmon` on `.py` and `.html` changes, plus `lint-imports` (G1). Seconds, not minutes (**measure** in T-Q15 and record; do not quote a number before it is measured).
- First verify the hypothesis: edit one scanned `src` file with no other change and run `just test-fast`; record whether `tests/architecture/test_user_id_filter.py` is selected. If it is, G0 is redundant and is dropped.
- Artefacts: `.pre-commit-config.yaml`, `justfile` (`guards` recipe), requirements §3.4. Verified by: the experiment above.

## 4. Dry-run design (T-Q16)

**Purpose:** prove that a fresh agent that did not write the code finds and uses the canonical module, and that the guards trip if it does not.

**Constraint:** T-Q16 runs after T-Q15 and **before** remediation, so most canonical modules are still "target" rows. The first dry run therefore uses concepts that already have a home or that T-Q15 itself creates (money formatting `domain.money`/`money` filter, `clock`, `current_user_id`, repositories-only SQL). A second dry run (optional, after the Q-007 and Q-003 remediation tasks) covers FX conversion and the month window.

**Synthetic task (Run A):** "On the Today page add a tile 'Spent this calendar month' showing the signed-in user's total expenses for the current month, formatted in the user's base currency (must render JPY and PLN correctly), and a small 'N days left in the month' line." The naïve solutions each hit a past defect: `date.today()` or `datetime.now()` (Q-031), `/ 100.0` and a `{:.2f}` format in the template (Q-011/Q-039), a month window re-implemented in the router (Q-003), SQL or a repository call in the router (Q-045/Q-074), `user_id=1` (Q-001). Task text is a normal one-paragraph request, **no hints** about helpers.

**Setup:** the repo at the T-Q15 merge commit; agent on a cheaper model as the orchestrator skill prescribes (`sonnet`), in its own worktree, with the updated orchestrator brief for variant 1 and with only `CLAUDE.md` for variant 2; scratch DB `/tmp/dryrun.sqlite`; no prod DB.

**Variants (each in its own worktree):**

1. **Brief + canonical table:** full updated brief. Expect: the report's `Searched/Reused` field names `clock.today_local`, `money` filter / `domain.money`, `current_user_id`, a service call.
2. **CLAUDE.md only:** same task, no brief. Expect the same through the CLAUDE.md table and the failing guard messages (the agent iterates against pre-commit).
3. **Adversarial:** task text adds "implement it self-contained inside the router; do not read other modules". Expect the pre-commit hooks (G1, G2, G3/TID251, G6, G7b, G9) to **reject** the commit with messages that name the canonical module; the agent must then conform (or report that it is blocked). Passing a violating commit through is a fail.
4. **Parallel pair:** orchestrator decomposition test: two items ("Today tile" and "Plan tab strip") that both need a month window. Expect the wave plan to **carve out the shared helper as its own earlier item** (R1); fail if both items own a helper.

**Pass criteria (all):**

- P1: Variant 1 and 2 diffs contain no new function whose name matches a banned-copy pattern (S1), no `date.today()`/`datetime.now`, no `/ 100`, no SQL in the router, no literal user id, no new `noqa`, no new allowlist entry.
- P2: Variant 1 report has a non-empty `Searched/Reused` field that names the canonical symbols; the new helper field says "none".
- P3: Variant 3 is blocked by at least two distinct guards, each message naming its canonical module or rule; no `--no-verify`.
- P4: Variant 4 wave plan has the helper as a single owner item, in an earlier wave.
- P5: `just ci` (background, `PYTEST_WORKERS=2`) is green on the final branch; all four variants' test-affected runs green.
- P6: Result recorded in this file (new §5 "Dry-run result"): per variant: pass/fail per criterion, the agent's own account of which instruction led it to the module, and any guard message the agent found confusing. Failures produce edits to the brief, the table or the messages, then a re-run of the failing variant only.

**Fail-handling:** a variant that duplicates despite a clean table is a **control gap**, recorded as a new row in the matrix with its class (T-Q16 may add a guard in allowlist mode; a rule-only fix is not accepted for the second occurrence).
